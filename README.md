# csfloat-watcher

Следит за новыми листингами CSFloat в заданных полосах float и шлёт сводку
в Telegram. Без зависимостей, Node 18+.

## Настройка

1. **Ключ CSFloat:** csfloat.com → аватар → **Profile** → вкладка **Developer**
   → New Key.
2. **Telegram-бот:** написать [@BotFather](https://t.me/BotFather) → `/newbot` →
   получить токен.
3. Вписать оба значения в `.env` (файл уже создан рядом со скриптом).
4. **Chat ID:** написать своему боту любое сообщение — иначе Telegram не выдаст
   ваш id и бот не сможет вам писать. Затем:

   ```bash
   node get-chat-id.js
   ```

   Скрипт найдёт id и сам впишет его в `.env`.

Проверить связь, не дожидаясь листингов:

```bash
node watch.js --test-telegram
```

Придёт тестовое сообщение — значит всё настроено.

## Запуск

```bash
node watch.js
```

Первый проход «прогревочный»: помечает текущие листинги как виденные и молчит.
Дальше присылает только появившееся после старта.

Флаги:

- `--once` — один проход и выход (для Планировщика задач Windows).
- `--alert-first` — не прогреваться, сразу прислать текущую выдачу.
- `--test-telegram` — отправить тестовое сообщение и выйти.

## Про рейт-лимиты

`pollMinutes: 5` — это 288 запросов в сутки на один предмет. Безопасно с
большим запасом: блокировки прилетают за плотность (несколько запросов в
секунду), а не за суточный объём. На `429` скрипт сам уходит в экспоненциальный
бэкофф: 60с → 2м → 4м, потолок 15 минут.

Ротацию ключей и cache-busting не делаем — это прямое нарушение правил
площадки и риск бана аккаунта с балансом.

## Запуск по расписанию

Чтобы не держать терминал открытым:

```bash
schtasks /create /tn "csfloat-watcher" /tr "node \"D:\Claude code\csfloat-watcher\watch.js\" --once" /sc minute /mo 5
```

Состояние между запусками живёт в `seen.json`, дубли не придут.

## Запуск в GitHub Actions (круглосуточно)

> **Состояние на 21.09.2026: приостановлено.** Перчатка куплена, слежка не
> нужна. Расписание в `.github/workflows/watch.yml` закомментировано, минуты
> Actions не расходуются. Репозиторий и секреты сохранены.
>
> **Чтобы возобновить:** снять комментарий со строк `schedule:` и `- cron:`
> в `.github/workflows/watch.yml`, запушить — и удалить `seen.json`, если
> хотите прогреться заново от текущего состояния рынка. Секреты уже на месте,
> заново их заводить не надо.

Работает без включённого компьютера. Всё уже настроено в
`.github/workflows/watch.yml`, остаётся создать репозиторий и положить секреты.

```bash
gh auth login
gh repo create csfloat-watcher --private --source=. --remote=origin --push
gh secret set CSFLOAT_API_KEY
gh secret set TELEGRAM_BOT_TOKEN
gh secret set TELEGRAM_CHAT_ID
```

Три последние команды спросят значение — вставьте его в ответ на приглашение.
Значения берутся из вашего локального `.env`.

Проверить: вкладка **Actions** → **csfloat-watcher** → **Run workflow**.

Особенности, о которых стоит знать:

- **Выключите локальный запуск.** Если `node watch.js` продолжит крутиться на
  компьютере, уведомления начнут дублироваться: у локальной копии и у Actions
  своё состояние, и каждая пришлёт своё.
- **Расписание — раз в час, и это упирается в квоту, а не в возможности.**
  Приватный репозиторий на бесплатном плане получает 2000 минут Actions в
  месяц, причём каждый запуск округляется вверх до целой минуты (наш идёт
  ~17 секунд, списывается минута). Почасовое расписание — это 720 минут в
  месяц, с запасом. Расписание `*/10` дало бы 4320 минут: квота кончилась бы
  за две недели, и Actions молча перестал бы запускаться.
- **GitHub не соблюдает расписание точно** — при нагрузке запуск
  задерживается, иногда на десятки минут.
- **Состояние живёт в `seen.json`**, который рабочий процесс коммитит обратно
  в репозиторий. Поэтому в истории будут накапливаться технические коммиты
  `state: seen listings` — это нормально.
- **Спящие репозитории отключаются.** Если в репозиторий 60 дней не приходит
  ни одного коммита от человека, GitHub останавливает расписание и присылает
  письмо. Коммиты от бота не считаются. Достаточно раз в пару месяцев зайти
  во вкладку Actions и нажать **Enable workflow**.
- **`.env` в репозиторий не попадает** — он в `.gitignore`. Ключи живут только
  в GitHub Secrets и на вашем компьютере.

## Ограничения

- Только предметы, которые можно купить сразу (`type=buy_now`). Аукционы
  исключены дважды: параметром запроса и локальной проверкой на `type` и
  `auction_details` — чтобы лот не просочился, если площадка поменяет
  поведение параметра.
- Приватные офферы между покупателем и продавцом в API не видны вообще.
- Работает, только пока включён компьютер. Если нужны уведомления
  круглосуточно — нужен всегда доступный хост.
- При интервале в 5 минут позиции, которые живут секунды, вы всё равно
  пропустите — их забирают боты. Реалистичная добыча — то, что появилось
  и повисело: 5–12% ниже рынка.
- `most_recent` отдаёт максимум 50 позиций за запрос. Для одной перчатки этого
  хватает с запасом.
- `seen.json` хранит последние 5000 id.
